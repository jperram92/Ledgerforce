# T-0162 — AP: preview the GP-009 confirmation journal from the posting engine (API)

## Goal
Split from T-0154 (DL-0540). UI principle P4 ("Show the journal before you post") needs the
journal that recording the bank's confirmation of a released payment batch will post (GP-009,
Approved; one entry per batch, one AP_CONTROL debit per bill, one bank credit for the bills'
total; customer refunds in the batch each preview their own GP-006 entry) **before** the
releaser records it. T-0057 has no preview path today (DL-0542). Build it in `@ledgerforce/ap`
with the ledger's `preview()` (the same command `confirmPaymentBatch` posts, minus the write),
and expose it read-only over HTTP for the T-0163 screen.

## Acceptance criteria (each maps to a test)
- AC-1 Given a released, unconfirmed batch and a confirmation date, when the preview is asked
  for, then it returns exactly the GP-009 lines (account, debit, credit, party, as decimal
  strings) and writes nothing (no journal, no allocation, no confirmation row) →
  `packages/modules/ap/src/payment-confirmation.db.test.ts`
- AC-2 Contract: the previewed lines equal the lines `confirmPaymentBatch` then posts for the
  same batch and date (P4 "Tested by") → `packages/modules/ap/src/payment-confirmation.db.test.ts`
- AC-3 HTTP: the route needs `ap.payment_batch.release`, answers 422 NOT_CONFIRMABLE / INVALID_BATCH
  in the module's words, 404 for another company's batch, and is tenant-isolated →
  `apps/api/src/ap/payment-confirmation.db.test.ts`

## Open questions
- Route shape: `POST /ap/payment-batches/:id/confirm/preview` (body as confirm) like the other
  preview routes (`apps/api/src/ap/bills.controller.ts`), or a GET with `confirmed_on`. Follow the
  bills/invoices preview precedent; additive route recorded in the decision log as T-0054/56/57 did.
- T-0057 is `blocked` on golden-approval provenance review; this card waits for it.
