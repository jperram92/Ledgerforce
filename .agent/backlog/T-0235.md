# T-0235 — Upload limits of the Mailgun inbound route from the environment

## Goal
T-0230 made the Mailgun inbound reader's limits (`InboundBodyLimits`: global and per-client
in-flight cap, byte budget, whole-body timeout, first-byte timeout, minimum rate and its grace)
configurable in code only, like the T-0215 limits before them. An operator who runs Mailgun from
one egress address, or a slower relay, cannot tune them without a code change.

## Acceptance criteria
- [ ] AC-1 (unit, config.test.ts) optional `LF_INBOUND_MAX_IN_FLIGHT`, `LF_INBOUND_MAX_PER_CLIENT`,
  `LF_INBOUND_FIRST_BYTE_TIMEOUT_MS`, `LF_INBOUND_MIN_BYTES_PER_SECOND` are read into
  `mailgunInbound.limits`, validated with bounds (per-client ≤ global; rate floor ≥ 4 KiB/s or 0
  only with an explicit opt-out); invalid values refuse start-up with a ConfigError
- [ ] AC-2 (unit, install contract) compose passes them to the api service only, unset by default
- [ ] AC-3 (docs) Docs/ops/install.md lists them next to the T-0230 runbook note
