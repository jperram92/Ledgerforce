# T-0148 — Close checklist and period list over HTTP (split from T-0090)

## Goal
T-0078 built the close checklist module only. The close screen (T-0090) needs these routes:
- `GET /periods?company_id=&from=&to=` lists fiscal periods with their status (`reports.run`).
- `GET /periods/:periodId/close-checklist?company_id=` returns the seven steps with who completed them and when (display name), plus the period status (`reports.run`).
- `POST /periods/:periodId/close-checklist/:step {company_id}` completes one step.
  - It needs `period.lock` and an Idempotency-Key, and is audited.
  - Status steps also pass the database's period permission checks (period.lock / period.close).
  - A replay by the same user answers 200 with the stored row. Another user answers 409 ALREADY_DONE.
  - OUT_OF_ORDER, BANK_UNRECONCILED, TB_NOT_BALANCED and SUBLEDGER_DIFFERENCE answer 422 with the module's message and, for the bank step, the accounts.

## Acceptance criteria
- [x] AC-1: GET routes return decimal-free JSON: dates are YYYY-MM-DD and timestamps ISO. A user without reports.run gets 403. Another tenant's period gets 404.
- [x] AC-2 (SS-UC10-01 over HTTP): the Finance Admin completes the steps in order. Each one returns user, time and resulting period status. An AR Clerk gets 403. A replay is idempotent. Refusals are 409/422 as above.
