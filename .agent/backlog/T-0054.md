# T-0054 — Payment batches with maker-checker and step-up release

## Goal
Create batch from approved due bills; exclude recently changed bank details with reason; creator ≠ releaser; >$10,000 needs two releasers; step-up on release.

## Context (design refs)
- Design: §6.5 rule 1, UC-06.
- Specs: [UC-06](../../Docs/specs/UC-06.md) · Register: [success-scenarios.md](../../Docs/specs/success-scenarios.md)
- Depends on: T-0052 (Bill approval workflow with SoD); T-0053 (Supplier/employee bank-detail change verification with cooling-off); T-0013 (MFA enforcement for finance roles and step-up re-authentication)

## Acceptance criteria (each maps to a test + SS id)
- [ ] **SS-UC06-01** (db-integration) — Batch created from 12 due bills. *Given* 12 approved bills due this week; *when* the AP Clerk creates a batch; *then* the batch contains 12 payments totalling the bills' open amounts.
- [ ] **SS-UC06-02** (db-integration) — Creator cannot release own batch. *Given* the SS-UC06-01 batch created by user A; *when* user A releases it; *then* release is denied with SOD_BATCH_SELF_RELEASE.
- [ ] **SS-UC06-03** (db-integration) — Release requires step-up MFA. *Given* user B without a fresh step-up; *when* B releases the batch; *then* the response is step_up_required; after step-up the release succeeds.
- [ ] **SS-UC06-04** (db-integration) — Batch over $10,000 needs two releasers. *Given* a batch totalling $25,000; *when* one releaser approves; *then* status is Partially released; a second distinct releaser completes it.
- [ ] **SS-UC06-05** (db-integration) — Recently changed bank details excluded with reason. *Given* one supplier whose bank details were verified 3 hours ago; *when* the batch is created; *then* that supplier's bill is excluded with reason BANK_DETAILS_COOLING_OFF.
