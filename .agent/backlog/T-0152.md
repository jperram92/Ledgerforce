# T-0152 — Customer refund over HTTP and the refund screen (split from T-0085)

## Goal
The refund half of SS-UC11-08: the AR Clerk requests a refund of a customer's credit balance
(`createCustomerRefund`, T-0055) from the credit-note screen, sees the customer's refundable
credit (`customerCredit`), and sees the GP-006 journal the refund will post when the payment
batch that pays it is confirmed.

## Blocked — needs the product owner (security gate)
The RBAC catalogue (`packages/shared/src/rbac/catalogue.ts`, ADR-0023) has **no refund
permission** (`ar.refund.*` or similar). Choosing one — a new permission and which role
templates hold it, or the reuse of an existing one such as `ar.credit_note.create` — changes the
security model and needs a **security** ADR, which the agents may not accept (AGENTS.md §6).
DL-0305 also notes that the refund route is a public API change that needs an ADR. Proposed
ADR id when the owner decides: next free ADR number (T-0085 had ADR-0064 reserved; not used).

## Acceptance criteria
- [ ] AC-1 (api-db) `PUT /ar/refunds/:id` (client id, idempotent) under the chosen permission: 403 without it, 404 for another tenant's party, REFUND_EXCEEDS_CREDIT 422, replay 200.
- [ ] AC-2 (api-db) `GET /ar/parties/:id/credit` (ar.read) returns balance / requested / available as decimal strings.
- [ ] AC-3 (db + api-db) a GP-006 journal preview for a requested refund through the engine's `preview()` (Dr AR control / Cr the bank account the batch will pay from), writing nothing — needs a decision on which bank account the preview shows before a batch exists.
- [ ] AC-4 (e2e-playwright, SS-UC11-08 refund half) refund screen with the preview, screenshots at 1440 and 390, axe, refusal and forbidden states.
- [ ] AC-5 RBAC matrix test updated for the permission.

## Open questions
- [ ] Which permission governs requesting a customer refund, and which role templates hold it? (security ADR, owner)
- [ ] Payment of the refund stays in the AP payment batch (SoD engine: create / approve / release, T-0054); this card must not add another payment path.
