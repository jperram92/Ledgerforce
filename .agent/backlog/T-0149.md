# T-0149 — Bank reconciliation over HTTP (split from T-0088)

## Goal
T-0058…T-0061 built the bank module (`@ledgerforce/bank`) only. The reconciliation screens (T-0088)
need thin NestJS routes over it. The prefix is `/bank-rec` because the web app owns `/bank/*`
(nginx sends each first path segment to one side, DL-0313):
- `GET  /bank-rec/accounts?company_id=` — the company's bank accounts, account number masked to the last 3 characters (`bank.read`).
- `GET  /bank-rec/accounts/:id/statements?company_id=` — imported statements, newest first (`bank.read`).
- `POST /bank-rec/accounts/:id/statements` — import a statement file (`bank.statement.import`).
- `POST /bank-rec/accounts/:id/matching-runs` — run exact matching and rule suggestions (`bank.reconcile`).
- `GET  /bank-rec/accounts/:id/lines?company_id=&statement_id=` — statement lines with their active match and open suggestions (`bank.read`).
- `POST /bank-rec/lines/:id/transaction` — create a transaction from an unmatched line, through the manual-journal rules and the posting engine (`bank.reconcile`).
- `POST /bank-rec/lines/:id/unmatch` — undo a line's match (`bank.reconcile`).
- `GET  /bank-rec/statements/:id/report?company_id=&closing_balance=` — the reconciliation report (`bank.read`).
- `POST /bank-rec/statements/:id/reconciliation` — complete the reconciliation of a statement that ties (`bank.reconcile`).

Rules for every route:
- Every POST needs an Idempotency-Key and is audited through `AuditTrail.describe`. A replay answers 200 with the stored result.
- Money is a decimal string.
- A row of another company or tenant is 404.
- Module refusals are 422 with the module's code and message.

## Acceptance criteria (each maps to a test)
- [x] AC-1: the read routes return masked accounts, statements, lines with match and suggestions, and the report as decimal strings. A user without `bank.read` (AR Clerk) gets 403. Another tenant's statement is 404. → `apps/api/src/bank/bank-rec.db.test.ts`
- [x] AC-2 (SS-UC08-02 over HTTP): importing the Harbour CSV creates 10 lines (201). The same file again answers 200 `duplicate_file`. A missing Idempotency-Key is 400. A bad file is 422. Another tenant's bank account is 404. → same file
- [x] AC-3 (SS-UC08-05 over HTTP): after a matching run, the fee line carries the rule suggestion. Accepting it creates and posts a transaction (201) and matches the line. A replay is 200 with the same entry. Without `bank.reconcile` the answer is 403. A transaction over the approval threshold is refused with 422 APPROVAL_REQUIRED. → same file
- [x] AC-4 (SS-UC08-06 over HTTP): the report ties. Completing it answers 201 and a replay 200. Another user gets 409. A closing balance that does not tie gets 422 NOT_BALANCED. Unmatching a line covered by the reconciliation gets 422 RECONCILED. Unmatch replays are 200. → same file
