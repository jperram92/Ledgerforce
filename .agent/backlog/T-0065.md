# T-0065 — Inbound mapping: Account/Contact/Product → Party/Product with idempotency

## Goal
Map CDC payloads to party/contact/product upserts by external id with idempotency key (record id + commit number), field ownership enforced.

## Context (design refs)
- Design: §5.5, §5.6 rule 1.
- Specs: [UC-01](../../Docs/specs/UC-01.md) · Register: [success-scenarios.md](../../Docs/specs/success-scenarios.md)
- Depends on: T-0064 (CDC subscriber via Pub/Sub API with replay-id store); T-0036 (Parties, roles, contacts and billing contact roles); T-0038 (Products, party posting profiles and product posting profiles)

## Open questions (→ research before start)
- [x] (RQ-0098) CDC body semantics (partial UPDATE, compound fields, delete/undelete), ordering across channels and polling, billing-role source, where inbound record problems go — answered (confidence medium; Salesforce docs read through search extracts only).

## Acceptance criteria (each maps to a test + SS id)
- [x] **SS-UC01-07** (db-integration) — Duplicate CDC event is idempotent. *Given* the same CDC event (same record Id + commit number) delivered twice; *when* both are processed; *then* one draft invoice exists and the second event is logged as duplicate. **T-0065 proves the master-data layer** (one party, the replay is a no-op and counted as duplicate, by CDC key and by SystemModstamp); the draft-invoice half is T-0069's.
- [x] **SS-UC01-12** (unit contract + db-integration) — Account → party (customer role, Type → party profile through `app.party_profile_mapping`, billing/shipping address, ABN, currency), Contact → party contact with billing roles from `LF_Billing_Role__c`, Product2 → product (Family → product profile, IsActive, optional tax code); LedgerForce-owned fields are never overwritten (design §5.5, ADR-0006).
- [x] **SS-UC01-13** (unit contract + db-integration) — An older change arriving after a newer one is ignored (stale) by (commit number, sequence) or SystemModstamp; DELETE archives, UNDELETE re-activates, a stale CREATE after a DELETE does not resurrect; nothing is deleted in LedgerForce.
- [x] **SS-UC01-14** (db-integration) — An unmapped picklist value or a validation failure raises an inbound sync issue (`app.salesforce_inbound_issue`, migration 0034) with field, value, message and payload — never silently dropped; a blocking problem leaves the record unapplied without blocking the channel; a later clean change resolves the issue.
