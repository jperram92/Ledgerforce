# T-0244 — Backup role hardening: detect missing lf_backup on upgrade, large-object refusal, pg_hba script robustness, /32 rule

## Goal
Security review r12 of T-0227 (DL-0899) passed with one medium (operational) and four low findings.
- M2: on an existing install backups fail nightly until the operator runs the manual upgrade step.
- L4 (unclear): with read-only switched off, lf_backup could likely create large objects (lo_creat).
- L5: the pg_hba restore does not run if the parse check itself fails; a pre-existing parse error makes the script fail every run.
- L6: a /0 CIDR is accepted. L7: the host may reach postgres from the internal network's gateway address.

## Acceptance criteria
- [ ] AC-1 (infra/db) a missing or misconfigured lf_backup is detected at backup start-up and fails loudly with a named error, or the idempotent role script runs from a one-shot compose service
- [ ] AC-2 (db) large-object creation functions are revoked from PUBLIC; a test with read-only off shows lf_backup cannot create large objects
- [ ] AC-3 (infra test) the pg_hba script restores the previous file whenever validation fails, tolerates a pre-existing parse error with a clear message, and refuses a /0 CIDR
- [ ] AC-4 (infra) the pg_hba rule is a /32 for the backup container address, or the gateway is excluded; documented in the runbook
