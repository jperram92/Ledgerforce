# T-0256 — Harden the @OwnTransactions mechanism

## Goal
Security review r13 of T-0243 (DL-0957) passed, with one medium and several low findings. M1: the guard that only read-method routes without @SoD may use @OwnTransactions runs per request and is untested; if a refactor dropped or inverted it, a POST or @SoD route could silently lose its audit row, SoD check and rollback with the suite still green.

## Acceptance criteria
- [ ] AC-1 (api-unit/api-db) interceptor tests: POST + @OwnTransactions → 500, handler not run, no audit row or write; GET + @OwnTransactions + @SoD → 500; class-level decorator ignored
- [ ] AC-2 (api-unit) startup check walks the controllers and refuses to boot on a bad combination
- [ ] AC-3 (api-db) TenantTx.run refreshes the step-up and permission view each run (L1); a role removed during the provider exchange gives 403, a denial audit row and no mailbox (L2)
- [ ] AC-4 (db) a mailbox flagged secret_rotation_failed_at is backed off (not polled every 5 min with the old token) and shown in the mailbox view (L3)
- [ ] AC-5 (api-unit) re-entrant TenantTx.run is refused (I2); the stale-verifier sweep cannot deadlock concurrent starts (L5)
