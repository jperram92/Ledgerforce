# T-0121 — AU templates v2 (accountant-review template corrections)

## Goal
Ship a **new version (v2)** of the three AU templates. Version 1 stays in the repository, marked
superseded in its `$comment` (no-delete, ADR-0014). v2 fixes the template MAJORs and two MINORs
from the accountant-reviewer persona review
(`.agent/evidence/T-0007/accounting-review-20261108.md`, DL-0280, triage DL-0283) so that, as
shipped, the templates misstate neither BAS labels nor the balance sheet. Design §3.2 (chart),
§3.6 (tax codes), §4.4 (posting profiles). This is template data, not posting behaviour. No golden
posting changes here; GP-007-A uses 1290 and is drafted in T-0124.

The template data is within the scope that the review proposed. Each change is an accounting
default, so before the card reaches `done` the persona re-reviews the v2 diff (DL-0282 pattern).

## Changes (v2, additive)
1. **Chart `au-services-smb` v2.**
   - 1500 Office equipment `defaultTaxCode: "CAP"`. Every `subtype: fixed_asset` account with
     `normalBalance: debit` defaults to `CAP`. Credit-normal accumulated depreciation accounts
     (1510) have no tax code.
   - New **1290 "Allowance for expected credit losses"**: type asset, subtype receivable (contra),
     `normalBalance: credit`, postable, `control: false`.
   - `suggestedSettings.ecl_allowance_account: "1290"` (setting key `ar.ecl_allowance_account`).
     Add the setting key wherever the settings registry lists `ar.bad_debt_account`.
2. **Profiles `au-services-smb-profiles` v2.**
   - `HARDWARE.asset` **empty**. The wizard gap step asks whether hardware is inventory or
     expensed on purchase. The cogs gap stays.
   - HARDWARE revenue maps to new chart account **4140 "Hardware sales"** (added to chart v2). 4190
     stays "Recoverable costs income" for REIMBURSABLE_EXPENSE and FREIGHT.
   - New **`EQUIPMENT`** product profile (own-use equipment): `asset: 1500`, purchase tax `CAP`.
   - **OVERSEAS_CUSTOMER: no `defaultTaxCode`**. With the T-0039 resolver this returns
     `NO_TAX_CODE` for products without their own code, so a person codes the line. This is the
     interim fix until ADR-0044 is built (T-0122/T-0123).
3. **Tax codes `au-gst` v2.**
   - Add **`EXP`** (GST-free export of goods, s 38-185 → BAS G1 + G2).
   - Add **`EXS`** (GST-free export of services, s 38-190 → G1 + G3). EXS is optional, and is
     included for an audit trail and because ADR-0044 R7 seeds it.
   - Both are effective-dated rows from 2000-07-01, kind `gst_free`. If the BAS mapping needs a
     distinct kind, that is a forward-only migration under the `migration` skill (as DL-0257).
4. **BAS mapping (T-0035's mapping table).**
   - `EXP` → G2.
   - `EXS` and `FRE` → G3.
   - **Purchase-side `INP` → G11 (+ G14 on the calculation sheet), not G13.** Sales-side INP → G4.
5. **W-codes.** Add `BAS-W1` and `BAS-W2` to the tax template with their BAS mapping. They are
   reported by **pay date** (wages paid), not by expense-line accrual, the same pattern as
   ADJ-BD/DL-0257. The golden world's private ids for them become template codes. The payroll
   bridge that uses them is Phase 1 (T-0100). This card only makes the codes and mapping exist.
