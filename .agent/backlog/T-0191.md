# T-0191 — Remittance account hardening

## Goal
Security review r8 of T-0180 (DL-0694) found two low points. L1: a designated remittance account that is archived and later re-activated prints on invoices again without a new approval (`packages/modules/bank/src/remittance.ts`). L2: in small-team mode one person can approve their own change with only the generic SoD exception record; for a payment-redirection risk every Owner and Finance Admin should be told of each change.

## Acceptance criteria
- [x] AC-1 (db) archiving the designated account clears or suspends the designation; re-activating it does not print it until a new change is approved
- [x] AC-2 (db) every approved remittance account change notifies all active Owners and Finance Admins (masked account, who requested, who approved), using the existing notification path
- [x] AC-3 (api-db) another tenant's change produces no notification in this tenant
