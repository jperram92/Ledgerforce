# T-0189 — Reconcile an expired Stripe refund send with Stripe

## Goal
T-0172 (ADR-0083, RQ-0163) refuses to send an approved Stripe refund automatically more than 23 hours after its approval (`KEY_EXPIRED`), because Stripe may have pruned the Idempotency-Key and a resend could refund twice. Such a refund stays approved and requested and its outbox delivery is a Sync issue. This card resolves it safely: list the PaymentIntent's refunds at Stripe (`GET /v1/refunds?payment_intent=`), find one whose metadata `lf_refund_id` is the refund document, and either record it (GP-006 Stripe variant, dated the Stripe refund date) or, if none exists, allow a resend with a new key after a second person confirms.

## Acceptance criteria
- [ ] AC-1 (contract, db) a Stripe refund found by `lf_refund_id` is recorded once, never sent again
- [ ] AC-2 (contract, db) with none found, the resend needs a second person and uses a new recorded key
- [ ] AC-3 the recorded-stripe stub supports GET with query matching (fixture first)
