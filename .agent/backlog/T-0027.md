## Report (claude, 2026-10-25, branch feat/T-0027-account-balance)

**Built**
- Migration `0023_ledger_account_balance.sql`: `app.account_balance` keyed by (tenant, company,
  account, period, dimension set, transaction currency) with base `debit_total`/`credit_total`
  and `txn_debit_total`/`txn_credit_total`; RLS ENABLE + FORCE, `tenant_isolation`, lf_app
  SELECT only. An AFTER INSERT FOR EACH STATEMENT trigger on `journal_line` (SECURITY DEFINER,
  owner lf_migrator, transition table) upserts the grouped, key-ordered sums of the inserted lines
  of non-draft entries with `ON CONFLICT DO UPDATE SET x = x + EXCLUDED.x`. A row trigger adds an
  entry's lines when it leaves draft. A guard lets an UPDATE only add (key fixed, no decrease) and
  refuses DELETE/TRUNCATE for every role.
- `packages/ledger/src/account-balance.ts`: `trialBalance()` (from account_balance) and
  `accountBalanceDrift()` (every key where account_balance ≠ sum of posted lines).
- Engine (`posting-engine.ts`): comments only — the balance is written by the database from the
  engine's single line insert, inside its `lf_posting` savepoint (kept minimal for the T-0030 merge).
- Research RQ-0032 (experiments E1–E6 on PostgreSQL 16.15), DL-0146..DL-0150, SS-PLAT-66/67.
- Unused pre-assigned ids: ADR-0028 (no ADR needed, see DL-0147).

**Tests** — RED first (`relation "app.account_balance" does not exist` / not implemented, 11 failed),
then GREEN: `account-balance.db.test.ts` 9 tests, `account-balance.prop.db.test.ts` 2 properties
(INV-balance-table + INV-tb-zero, INV-reversal; default numRuns). SS-PLAT-67 posts 36 entries on
12 connections across eight number series, opposite directions, locks held 20 ms.

**Mutation check** (scratchpad `t0027/mutate.py`; each mutant applied alone, then restored):

| Mutant | Result |
|---|---|

| M2 draft lines counted | killed (draft test, drift test) |
| M3 txn debit total sums the credit side | killed (7, incl. both properties) |
| M4 read-then-write instead of atomic upsert | killed by SS-PLAT-67 (the guard refuses the stale write as a decrease) |
| M4b M4 with the guard off | killed: SS-PLAT-67 shows lost updates (e.g. 1010 dr 3.4844 instead of 55.8522) |
| M5 guard allows decreases | killed |
| M6 lf_app granted INSERT/UPDATE/DELETE | killed (42501 test) |
| M7 no balance when an entry leaves draft | killed |
| M8 currency dropped from the key | killed (posting test, both properties) |
| M9 drift verifier ignores debit | killed |
| M10 `ORDER BY account_id DESC` | survived — equivalent: still one consistent order for every transaction |
| M11 order by side (debit row first) | killed: 40P01 deadlock in SS-PLAT-67 |

serialises the postings of one series per company (RQ-0032 finding 9, DL-0150); the test was
changed to eight series before the final run.

**Not proven / limits**
- Two caller transactions that each post several entries can still lock balance rows in
  different orders across statements; PostgreSQL then aborts one with 40P01 (nothing half-written).
  Not exercised by a test.
- Lines written with no tenant set (superuser, outside the application) are skipped; the drift
  verifier would report them.
- A total above NUMERIC(19,4) fails the posting (22003); not tested.
