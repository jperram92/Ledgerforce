# T-0044 — Batch billing run: approve, post as one job with per-invoice isolation

## Goal
Approved batch posts in a pg-boss job; each invoice in its own transaction; failures to exception list; re-run idempotent; batch summary report.

## Context (design refs)
- Design: UC-02.
- Specs: [UC-02](../../Docs/specs/UC-02.md) · Register: [success-scenarios.md](../../Docs/specs/success-scenarios.md)
- Depends on: T-0043 (Batch billing run: selection and preview); T-0042 (Email delivery (SMTP) via outbox for invoices, statements, reminders, remittances); T-0024 (Gapless document numbering series)

## Open questions (→ research before start)
- None known. Re-read design refs at claim; open an RQ for anything unclear.

## Acceptance criteria (each maps to a test + SS id)
- [x] **SS-UC02-02** (db-integration) — Approved batch posts all invoices in one job. *Given* the SS-UC02-01 preview; *when* the batch is approved; *then* 40 invoices are posted by one job, each journal matches the posting rules, and a batch summary report lists 40 entries.
- [x] **SS-UC02-03** (db-integration) — One failure does not roll back the others. *Given* 40 Accounts where one has an inactive party; *when* the approved batch runs; *then* 39 invoices post, 1 is in the exception list with its reason, and no posted invoice is rolled back.
- [x] **SS-UC02-04** (db-integration) — PDFs emailed to Billing To and CC. *Given* each Account has a Billing To and one CC contact; *when* the batch posts; *then* the SMTP sink receives 39 emails with the PDF attached and correct To/CC recipients.
- [x] **SS-UC02-05** (db-integration) — Re-running a crashed batch is idempotent. *Given* a batch job killed after 20 invoices; *when* the job is re-run; *then* 40 invoices exist in total, none duplicated.
- [x] **SS-UC02-06** (db-integration) — Consecutive gapless numbers; failed invoice consumes none. *Given* the SS-UC02-03 batch; *when* numbers are assigned; *then* the 39 posted invoices have consecutive numbers with no gap.
