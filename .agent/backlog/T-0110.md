# T-0110 — Salesforce write-back: scratch-org e2e and refund/aged-AR write-back scenarios

## Goal
Prove the three write-back scenarios that T-0067 could not prove. T-0067 built the outbox write-back:
the `writeBack` v1 payload contract, sObject Collections batches, outage handling (ADR-0036,
RQ-0040). These scenarios need documents that did not exist then:
- a draft invoice from Closed Won (T-0069), seen in a real scratch org;
- refunds (T-0055);
- aged receivables (T-0049).

Design §5.4, §5.6. Split from T-0067 (DL-0205).

## Acceptance criteria (each maps to a test + SS id)
- [ ] **SS-UC01-02** (e2e-playwright, screenshot evidence) — Salesforce shows "Draft" within 60
  seconds. *Given* SS-UC01-01 has run against a scratch org; *when* 60 seconds elapse; *then*
  Opportunity.LF_Invoice_Status__c = "Draft" (screenshot of the Opportunity record). The invoice
  module emits `invoice.drafted` with the `writeBack` snapshot (ADR-0036 rule 1).
  → `tests/e2e/salesforce/writeback-draft.spec.ts`
- [ ] **SS-UC11-05** (contract) — Salesforce shows net amount paid. *Given* SS-UC11-03 confirmed;
  *when* write-back runs; *then* Opportunity.LF_Amount_Paid__c = 1,155.00.
  → `packages/connectors/salesforce/src/writeback/writeback.refund.contract.test.ts`
- [ ] **SS-UC12-05** (db-integration) — Salesforce values reconcile to LedgerForce aged AR. *Given*
  a party with open and overdue invoices; *when* write-back completes; *then* LF_Balance_Due__c and
  LF_Overdue_Amount__c equal the aged-AR totals for the party.
  → `apps/worker/src/salesforce-writeback.aged-ar.db.test.ts`
