# T-0154 — UI: bank file (ABA) download on the payment batch screen (follow-up of T-0087)

## Goal
UC-06 step 3 on the payment batch screen built in T-0087: once a batch is released, a releaser
downloads the ABA (Cemtex) file (`POST /ap/payment-batches/:id/aba`, T-0056). The file is a
download only; nothing on the screen shows an unmasked account number.

**Scope split (DL-0540).** The card first also covered recording the bank's confirmation (UC-06
step 4) with the GP-009 journal. P4 needs that journal previewed before it posts and there is no
preview path yet (DL-0542), so the confirmation moved to **T-0162** (GP-009 preview in the AP
module and API) and **T-0163** (the confirmation on this screen). The original AC-2 and the
confirmation refusals of AC-3 (422 NOT_CONFIRMABLE, 503 queue_not_configured) now live on T-0163.

## Acceptance criteria (each maps to a test)
- AC-1 Given a released batch, when a releaser presses "Download the bank file", then the browser
  receives the `.aba` attachment (exact bytes, the API's file name) and the screen notes it was
  made and that the download is in the audit log; the full account numbers never show →
  `tests/e2e/web/payment-batch.spec.ts` (`SS-UC06-11 …` at 1440 and 390)
- AC-2 Moved to T-0163 (DL-0540).
- AC-3 Someone without `ap.payment_batch.release` sees no bank-file action; before release the
  screen says why there is no file; refusals (422 BANK_NOT_CONFIGURED, NOT_RELEASED,
  INVALID_ABA_DATA, 503 kms_not_configured, 403 sod_violation) in plain words; a 401
  step_up_required shows the step-up prompt and nothing is retried on its own →
  `tests/e2e/web/payment-batch.spec.ts` (`T-0154 AC-3 …`, `T-0154: …`),
  `apps/web/src/purchases/payments-logic.test.ts` (`bank file words [T-0154]`)

## Open questions
- Should the GP-009 journal be previewable before confirmation? Answered (DL-0542): yes, P4
  requires it; T-0057 has no preview path, so T-0162 builds it from the ledger's `preview()`.
  No RQ was needed (P4 and the existing preview routes settle it).
- The ABA and confirm routes are gated by `ap.payment_batch.release` only, without a SoD step or
  step-up (DL-0292, DL-0304: design §6.5 has no rule for them; a new SoD step or step-up on them
  is a security-model change, a human gate). The screen goes through the API's checks and handles
  a step-up or SoD answer should the owner add one (DL-0541). Raised for the owner in the report.
