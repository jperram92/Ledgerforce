# T-0172 — Stripe refund through the approved refund document

## Goal
ADR-0074 (DL-0477 item 3): a Stripe refund is sent only after approval. Today
`refundCreditViaStripe` (T-0074, `packages/connectors/stripe/src/refund.ts`) refunds a credit
note's credit directly, and `createCustomerRefund` refuses `method: stripe` with
`METHOD_NOT_AVAILABLE`. This card lets `PUT /ar/refunds/:id` accept `stripe` and makes
`POST /ar/refunds/:id/approve` (the SoD-checked step) call Stripe and post the GP-006 Stripe
variant (Dr AR control / Cr Stripe clearing), so no Stripe refund leaves without a checker.

## Acceptance criteria
- [ ] AC-1 (db) a requested Stripe refund is not sent until approved; approval sends it once (Stripe idempotency key) and posts GP-006 Stripe variant line for line → `packages/connectors/stripe/src/*.db.test.ts`
- [ ] AC-2 (api-db) `POST /ar/refunds/:id/approve` for a Stripe refund: SOD_REFUND_SELF_APPROVAL for the creator, replay returns the same refund → `apps/api/src/ar/refunds.db.test.ts`
- [ ] AC-3 the direct `refundCreditViaStripe` path is no longer reachable without an approved refund document (or is routed through it) → test as AC-1
