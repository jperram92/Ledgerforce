# T-0227 — Least-privilege lf_backup role (split from T-0143, DL-0883)

## Goal
The compose `backup` service connects as the `postgres` superuser because `pg_dump` must read
past FORCEd RLS (RQ-0183 Finding 3, ADR-0101). Add a login role `lf_backup` with `BYPASSRLS` and
`pg_read_all_data` only (no write, no DDL, no superuser), created by the cluster bootstrap and by
an upgrade step for existing installs, and switch the backup service to it.

## Acceptance criteria
- AC-1 `createBackup` as `lf_backup` produces a backup the restore drill verifies; `lf_backup`
  cannot INSERT/UPDATE/DELETE any table nor create objects → `packages/db/src/ops/backup-role.db.test.ts`
- AC-2 Bootstrap creates the role idempotently; existing installs get it through a documented,
  idempotent step → same file + `infra/test/install-contract.test.ts`
- AC-3 Compose `backup` holds an `lf_backup_password` secret and no longer `postgres_password`
  → `infra/test/install-contract.test.ts`

## Open questions
- Security ADR for a BYPASSRLS role (AGENTS.md: changing bootstrap/*.sql is a security change).
