# T-0105 — Server-side sessions: idle/absolute timeouts, revoke-all, session TenantResolver

## Goal
Tenant-scoped `app.session` table and a `SessionTenantResolver` that turns the `lf_session`
cookie (`<tenant_id>.<session_id>.<secret>`) into a tenant + user for the T-0104 interceptor.
Includes 30-minute idle and 12-hour absolute expiry, revoke-all through `app_user.session_epoch`,
and single-session logout. Implements ADR-0016 (Proposed, security).

## Context (design refs)
- Design §6.2 (session policy, revoke-all), §6.7 (RLS); ADR-0016; RQ-0013; RQ-0015.
- Split out of T-0011 on 2026-10-24 by claude so sessions (no IdP needed) and OIDC login
  (needs the in-process IdP) each fit one session. T-0011 now depends on T-0105.
- MFA enforcement is T-0013. This task only stores `amr`/`acr` on the session.

## Open questions (→ research before start)
- [x] Where the tenant comes from before RLS can apply: from the cookie, verified under RLS (ADR-0016 option 3).

## Acceptance criteria (each maps to a test + SS id)
- [ ] **SS-PLAT-20** (db-integration), session part — *Given* a user with a session; *when* it
  is idle 31 minutes, past 12 hours absolute, revoked by an epoch bump, logged out, or presented
  with a tampered secret or a forged tenant id; *then* the API answers 401 (`session_expired` or
  `unauthenticated`) and runs no tenant query. A valid session resolves to the right tenant and
  user, and RLS still filters.

## Expected results defined before build
- `apps/api/src/auth/session.db.test.ts`: tests named `SS-PLAT-20: …` for each case above, using an injected clock.
- The cross-tenant suite automatically covers `app.session` (SS-PLAT-04 stays green).
