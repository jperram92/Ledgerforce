## Report (claude, round 6, 2026-10-25)

**What already existed.** T-0025 shipped `preview()` (steps 1, 3, 4, 5, no write) and SS-PLAT-65
proved "no journal rows" with a five-value snapshot in a READ ONLY transaction. Preview did not
write anything; no migration was needed (0026 unused).

**What was wrong (RQ-0035).** Preview and post disagreed: an unknown `createdBy` (post failed on
the FK, raw 23503), an override by a user without `period.lock.override` (post failed in the
trigger, raw 42501), and a used idempotency key (post replays or throws IDEMPOTENCY_CONFLICT;
preview built a fresh journal). The property test found the first of these on the base code
(counterexample `user=unknown` → preview ok, post 23503; scratchpad `t0026/red-prop.txt`).

**What was built.**
- `packages/ledger/src/posting-engine.ts`: shared validate step checks createdBy (UNKNOWN_USER)
  and the override permission (OVERRIDE_NOT_PERMITTED) before any write (DL-0163); preview looks
  up the key without a lock → ALREADY_POSTED (with entryId/entryNo) or IDEMPOTENCY_CONFLICT
  (DL-0164). `posting-command.ts`: three new codes; PostingError carries entryId/entryNo.
- Test helpers (`@ledgerforce/ledger/testing`): `databaseFingerprint` (every table in every
  non-system schema: count + content hash; every sequence's last_value) and
  `storedJournal`/`expectedJournal` (DL-0165).
- Tests: `engine.preview.db.test.ts` (5 tests: five document kinds + lock-date redirect, read-write
  and READ ONLY, refusal parity, used keys), `engine.preview.prop.db.test.ts` (INV-preview,
  INV-preview-outcome with single-fault commands and expected codes, default numRuns),
  `packages/outbox/src/preview.db.test.ts` (pg-boss installed; outbox_event and pgboss.job
  unchanged by preview; post then adds one event and one job).

**Mutation check** (scratchpad `t0026/mut/`, 7 mutants on posting-engine.ts, all killed):
M1 skip the key lookup in preview (1 test failed); M2 drop the UNKNOWN_USER check (2); M3
override check never fails (2); M4 preview takes a number (5); M5 preview creates dimension sets
(4); M6 preview inserts a period override inside a savepoint and rolls back (3, caught by the
`audit.audit_log_id_seq` sequence value); M7 ALREADY_POSTED carries the wrong entry id (1).

**Gates (worktree):** pnpm install 0; pnpm test 47 files / 628 tests passed; pnpm test:db 46
files / 747 tests passed; node --test scripts/agent/test 81/82 (known worktree-path failure in
run.test.ts, see protocol); pnpm lint 0; pnpm typecheck 0; pnpm format:check 0; pnpm audit --prod
0 (no known vulnerabilities).

**Open questions for the human:** none blocking. ALREADY_POSTED is a design choice (DL-0164); the
UI may prefer to show the stored entry instead of an error, which it can do with `entryId`.

**Not proven / limits:** subledger entries and posting rules do not exist yet; when they land in
`write()`, any database-only check there needs an in-memory twin or preview diverges (the
fingerprint and parity property will catch it). Preview takes no lock, so a concurrent change
(period closed, account archived) between preview and post can still make post refuse — by
design.
