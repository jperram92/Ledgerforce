## Report (claude, worktree sub-agent, round 5 — 2026-10-25)

**Built** (branch `feat/T-0030-outbox-worker` from cef9f8f):
- Migration **0024** `0024_outbox.sql`: `app.outbox_event` and `app.outbox_inbox` are tenant-owned (RLS ENABLE+FORCE, `tenant_isolation`, lf_app SELECT/INSERT, and append-only for every role through the 0021 history trigger). Schema `pgboss` is owned by lf_migrator; lf_app gets USAGE plus default DML privileges and no CREATE, TRUNCATE or TRIGGER.
- `packages/outbox` (new):
  - `enqueue(trx, boss, msg)` writes the event and its pg-boss job through the caller's transaction (`fromKysely(trx)`). The job id is the event id and the payload is `{ tenantId, eventId }` only.
  - `ledgerOutbox(boss)` implements the engine's existing `PostingOutbox` hook (topic `ledger.entry.posted`).
  - `HandlerRegistry` + `deliver`: a per-handler inbox row is committed in the same tenant transaction as the handler's effect.
  - Queue policy: backoff 1 min → 6 h over 10 retries, a 5-minute lease, 400-day retention and a dead-letter queue.
  - `installOutboxQueues`, and a test harness built on pg-boss's `TestClock` (no sleeps).
- `apps/worker` (first package.json): `startOutboxWorker` (pg-boss `work`), `installQueue` and `startMaintenance` (lf_migrator only, refuse other roles) and the `install-queue` CLI.
- Engine edit: only the `NO_OUTBOX` doc comment in `posting-engine.ts`. There is no behaviour change, so it can't conflict with T-0027's write step.
- Research and decisions: RQ-0033; DL-0151..0155; ADR-0029 not used (ADR-0008 is already the pg-boss dependency ADR).
- Scenarios: SS-PLAT-24 green; SS-PLAT-68 and SS-PLAT-69 added (green).

**Tests:**
- SS-PLAT-24 (crash after send): worker 1 fetches the job and commits the handler's effect, then stops without acknowledging it. The TestClock moves past the lease and the first backoff, the owner runs `supervise`, and worker 2 receives the **same job id** with `retryCount` 1. The inbox skips the handler, so the effect count is still 1 and the job completes.
- Also covered: a failing handler leaves no effect and no inbox row, and the retry applies the effect once; a forged tenant id cannot read the event (RLS).
- SS-PLAT-68: commit, caller rollback, failed job insert and replay.
- SS-PLAT-69: append-only rows, ownership and privileges, and install role checks.
- RED captured first: "not implemented" and `schema "pgboss" does not exist`.

**Mutation check:** 10 hand mutants, 10 killed, each restored:
- inbox ignored
- job sent outside the transaction
- job id ≠ event id
- effect committed apart from the inbox
- tenant data in the payload
- lf_app UPDATE on events
- TRUNCATE on pgboss
- no role check on install
- job contract accepts extra fields
- backoff cap changed
