# T-0190 — Cancel a Stripe refund that Stripe refused

## Goal
T-0172 leaves a Stripe refund that Stripe refuses permanently (for example `charge_disputed`) approved and requested, with a Sync issue; its amount keeps counting as requested in `customerCredit`, so the credit cannot be refunded another way. Add `POST /ar/refunds/:id/cancel` (permission `ar.refund.create` or `ar.refund.approve`, SoD as ADR-0074) that moves a requested refund to `cancelled` when no Stripe refund was recorded for it (the 0055 guard already allows requested → cancelled), and shows it on the refund region.

## Acceptance criteria
- [x] AC-1 (api-db) a refused Stripe refund can be cancelled; a sent one cannot; another tenant's is 404
- [x] AC-2 (db) a cancelled refund no longer counts as requested; the outbox handler then does nothing
- [x] AC-3 (e2e) the refund region offers Cancel for a refused Stripe refund

  Owner and Finance Admin hold both). It cancels a requested Stripe document, approved or not,

  holds a live refund for it (review r8 R2), 422 `NOT_CANCELLABLE` when paid or a bank refund

  money moves; the cancel is audited. The outbox handler does nothing for a cancelled document.
  GET shows a failed send from its open Sync issue, so Cancel survives a reload. The region offers
  Cancel to people with `ar.refund.create` for a failed send that is not SENT_NOT_POSTED.
