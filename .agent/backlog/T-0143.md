# T-0143 — Encrypted backup and restore drill (split from T-0097)

## Goal
Supersedes T-0097 (part; carries its AC-1). Nightly encrypted logical backups of the LedgerForce
database and a scripted restore drill that restores a backup into a fresh database and runs the
journal hash-chain verifier (`verifyChain`, ADR-0017) for every company; design §6.9 (backups,
PITR targets RPO 15 min / RTO 4 h hosted, quarterly restore drills).

## Acceptance criteria (each maps to a test)
- AC-1 (was T-0097 AC-1) Given a migrated database with posted journals in two tenants When the
  backup tool dumps it and the restore drill restores it into a fresh database Then the drill
  reports every company's chain `ok` with the same entry counts and exits 0
  → `packages/db/src/ops/restore-drill.db.test.ts` (local PostgreSQL 16 test harness)
- AC-2 Given a backup whose bytes were altered, or a restored chain with a tampered line, When
  the drill runs Then it exits non-zero naming the failure → same file
- AC-3 The backup file at rest is encrypted (no plaintext table data in the file) and decrypts only
  with the configured key → same file
- AC-4 Compose ships a nightly backup service with a retention setting and a runbook in
  `Docs/ops/backup-restore.md` → `infra/test/install-contract.test.ts` (compose run verified in CI
  only: no Docker locally, DL-0007)

## Open questions
- Encryption tool for backups at rest (age vs `openssl cms`/`gpg` vs the KMS adapter, ADR-0038);
  key custody for self-hosters → RQ-0142, and an ADR (security) for the choice.
- PITR (WAL archiving, e.g. pgBackRest/WAL-G) for the hosted RPO 15 min: in this card or a later
  hosted-ops card → RQ-0142.
