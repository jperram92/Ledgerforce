# T-0160 — Bank: accept a candidate suggestion (split from T-0150)

## Goal
Split from T-0150 (DL-0530). Ambiguous receipt/payment candidates are listed on the match screen
as "Suggested: RCT-…", but neither the module nor the API can accept one. Add `acceptSuggestion`
to `@ledgerforce/bank` (records the match with method `suggestion`, closes the suggestion as
`accepted` and the line's other open suggestions as `dismissed`, through the existing
`recordMatch`; no posting, so no golden posting is involved), a
`POST /bank-rec/lines/:id/suggestions/:suggestionId/accept` route (bank.reconcile, Idempotency-Key,
audited, replay 200 for the same user) and an "Accept" button beside a candidate suggestion on
the match screen.

## Acceptance criteria (each maps to a test)
- [ ] AC-1: accepting a candidate suggestion matches the line to that entry with method
  `suggestion`; a closed (accepted or dismissed) suggestion is refused with SUGGESTION_CLOSED; a
  rule suggestion is refused (it needs a transaction). → `packages/modules/bank/src/matching.db.test.ts`
- [ ] AC-2: over HTTP: 200 with the match, 422 SUGGESTION_CLOSED for a closed one, 403 without
  bank.reconcile, 404 for another company's line, replay by the same user is 200.
  → `apps/api/src/bank/bank-rec.db.test.ts`
- [ ] AC-3: the match screen offers "Accept" on a candidate suggestion and the line shows as
  matched afterwards; an Auditor sees no Accept button. → `tests/e2e/web/bank-suggestion.spec.ts`

## Open questions
- None. `app.bank_match.method` already allows `suggestion` (migration 0050), so no migration.
