# T-0255 — Close the post-withdrawal Stripe window

## Goal
Security review r13 of T-0207 (L1, DL-0956): if a Stripe send reached Stripe and the database session then died (failover, killed connection, crash), the approval rolls back and the party lock is released. A clerk can withdraw the "failed" request at once, the lookup finds nothing, and the credit is freed; Stripe then completes the refund. The 30 s timeout does not bound this, because it only limits how long we wait. A later Stripe refund is refused and the nightly sweep (T-0208) reports it, but a same-day bank refund of the freed credit is not checked, so the customer could be paid twice before the report.

## Acceptance criteria
- [ ] AC-1 (db) withdrawing a Stripe refund document queues a read-only re-check at Stripe 5–15 minutes later; a refund found then is reported as a Sync issue (no money moves)
- [ ] AC-2 (db/api-db) a bank refund request or approval for a customer is refused while a Stripe refund for one of their withdrawn/cancelled documents is open at Stripe or within the re-check window (named error)
- [ ] AC-3 (docs) ADR (security, superseding the DL-0951 risk statement), RQ-0189 and DL-0951 wording corrected to describe the real window
- [ ] AC-4 (db) two-transaction test for the cancel-first batch race with concurrent transactions (asserting the cancel blocked)
