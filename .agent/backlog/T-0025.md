# T-0025 — Posting engine pipeline (command → validate → resolve → build → check → write)

## Goal
The single write path to the ledger: idempotent command handling, validation, line building, in-memory invariant check, single-transaction write of journal + outbox row.

## Context (design refs)
- Design: §3.9, §4.6 "modules never write ledger tables".
- Specs: — · Register: [success-scenarios.md](../../Docs/specs/success-scenarios.md)
- Depends on: T-0021 (Immutability triggers and privilege model for ledger tables); T-0023 (Periods, close status matrix and lock-date policy); T-0024 (Gapless document numbering series); T-0014 (Append-only audit log (separate schema)); T-0022 (Hash chain per company and verification report)

## Open questions (→ research before start)
- Idempotency under concurrency → [RQ-0030](../../Docs/research/RQ-0030-posting-idempotency-concurrency.md) (resolved: no migration; advisory lock + replay + savepoint fallback).

## Acceptance criteria (each maps to a test + SS id)
- [x] (from T-0020, DL-0074) The engine refuses any amount with more than 4 decimal places (and rates with more than 8) before writing, with a clear error. PostgreSQL would otherwise round it silently on insert. Add a unit test at the command boundary. → `packages/ledger/src/posting-command.test.ts` (AC-1 tests: AMOUNT_SCALE / RATE_SCALE, refused before any SQL via `testing/untouchable-trx.ts`; trailing zeros beyond the scale are accepted, DL-0138).
- [x] **SS-PLAT-14** (db-integration) — Same idempotency key posts once. *Given* a posting command; *when* it is submitted twice with the same idempotency key; *then* one entry exists and the second call returns the first result. → `packages/ledger/src/engine.idempotency.db.test.ts` (sequential, 8 concurrent, concurrent repeat that would now be refused, key committed outside the lock, reuse for another document → IDEMPOTENCY_CONFLICT, per-company scope) and `INV-idempotent` in `posting-invariants.prop.db.test.ts`.
- [x] **SS-PLAT-64** (unit + db-integration, added) — invalid commands are refused with a typed error and write nothing. → `packages/ledger/src/posting-command.test.ts`, `posting-balance.prop.test.ts` (INV-balance, before SQL), `engine.pipeline.db.test.ts`.
- [x] **SS-PLAT-65** (db-integration, added) — a valid command posts as one numbered, chained entry in one transaction; preview writes nothing. → `packages/ledger/src/engine.pipeline.db.test.ts`; `INV-balance` / `INV-tb-zero` in `posting-invariants.prop.db.test.ts`.
