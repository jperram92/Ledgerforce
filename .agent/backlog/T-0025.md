# T-0025 — Posting engine pipeline (command → validate → resolve → build → check → write)

## Goal
The single write path to the ledger: idempotent command handling, validation, line building, in-memory invariant check, single-transaction write of journal + outbox row.

## Context (design refs)
- Design: §3.9, §4.6 "modules never write ledger tables".
- Specs: — · Register: [success-scenarios.md](../../Docs/specs/success-scenarios.md)

## Acceptance criteria (each maps to a test + SS id)
- [ ] (from T-0020, DL-0074) The engine refuses any amount with more than 4 decimal places (and rates with more than 8) before writing, with a clear error. PostgreSQL would otherwise round it silently on insert. Add a unit test at the command boundary.
- [ ] **SS-PLAT-14** (db-integration) — Same idempotency key posts once. *Given* a posting command; *when* it is submitted twice with the same idempotency key; *then* one entry exists and the second call returns the first result.
