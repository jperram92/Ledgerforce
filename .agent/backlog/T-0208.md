# T-0208 — Stripe refund reconciliation in the refund region, and a nightly sweep

## Goal
T-0189 (ADR-0091) added three API routes:
- `POST /ar/refunds/:id/stripe-check`: records a refund Stripe holds, or reports what Stripe holds;
- `PUT /ar/refunds/:id/stripe-resends/:resendId`: asks for a resend;
- `POST …/confirm`: a second person confirms the resend, with a step-up.

The refund region does not offer them yet. Separately, review r8 R2 strays are found only one
document at a time. An R2 stray is a refund Stripe holds with `lf_refund_id` while the document is
unapproved or has no `stripe_refund` row.

## Acceptance criteria
- [ ] AC-1 (e2e) a Stripe refund whose send failed or expired offers "Check with Stripe" to
      Approvers. The region shows the outcome: recorded, approve to record it, or nothing at
      Stripe with failed refund ids. It offers "Ask to send again" (with a reason) when
      `resendable`, and "Confirm and send again" to a different person, behind the step-up prompt.
- [ ] AC-2 (db, contract) a nightly worker job lists requested Stripe documents of each active
      tenant. It runs the read-only lookup and opens one Sync issue per document Stripe holds a
      live refund for. It records nothing and creates nothing at Stripe.
- [ ] AC-3 the GET view shows a waiting resend (who asked, when, why).
