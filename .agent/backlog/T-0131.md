# T-0131 — AR invoices read and journal-preview API (split from T-0083)

## Goal
The data side of SS-UC01-10, which T-0083's screens need:
- `listInvoices` / `getInvoice` and `previewInvoiceJournal` in @ledgerforce/ar. The preview is the posting engine's `preview()` of exactly the command `approveInvoice` posts, so the journal-building step is shared and writes nothing.
- An `ar/invoices` controller: GET list, GET :id, GET :id/journal, POST :id/approve. RBAC is `ar.read` / `ar.approve`, approve needs an idempotency key, and money travels as decimal strings.

## Acceptance criteria
- [ ] AC-1 (db-integration, SS-UC01-10 data layer): for a draft GP-001 invoice, `previewInvoiceJournal` returns exactly the GP-001 lines (accounts, debit/credit, party) and writes nothing; after `approveInvoice` the posted journal equals the preview.
- [ ] AC-2 (api-db): the routes answer with the right status codes, permission denials and tenant isolation; approve replays idempotently.
- [ ] AC-3: `approveInvoice` behaviour is unchanged (existing invoice lifecycle, golden and batch tests still pass).

- Split from T-0083 on 2026-11-13: no invoice HTTP routes or read functions existed.
