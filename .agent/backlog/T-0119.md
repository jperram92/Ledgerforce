# T-0119 — Chromium in the worker image and PDF rendering as a worker job

## Goal
Ship a headless Chromium in the worker image (ADR-0045 rule 5) and render invoice PDFs in the worker on `ar.invoice.posted`, storing the PDF for email (T-0042) and the Salesforce PDF link.

## Context
- Split from T-0041 (renderer and templates done there, DL-0269). Design §7.1, §5 (LF_Invoice__c PDF link).
- Runtime image is Alpine (DL-0248); Chromium adds packages to the image vulnerability gate (ADR-0043) — remediate, never weaken the gate.
- playwright-core 1.63.0 pins a Chromium build; on Alpine use the distribution chromium with `executablePath`, or a Debian-slim worker stage — research which keeps the image gate green.

## Open questions (→ research before start)
- [ ] Alpine chromium vs pinned Playwright build: compatibility with playwright-core 1.63.0 and image-scan results.
- [ ] Where PDFs are stored (database bytea vs object storage in the self-hosted stack).

## Acceptance criteria
- [ ] AC-1 Worker image renders the GP-001 invoice PDF (compose smoke).
- [ ] AC-2 `ar.invoice.posted` handler stores the PDF once (idempotent) and the security image gate stays green.
- [ ] AC-3 The worker registers `invoiceEmailHandler` (T-0042) with SMTP settings from the compose environment (LF_SMTP_URL, LF_SMTP_FROM).
