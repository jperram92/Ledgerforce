# T-0150 — Bank: journal preview, candidate suggestions, large statement files (follow-up of T-0088/T-0149)

## Goal
Gaps found while building T-0149 and T-0088 (DL-0482):
- **Journal preview (P4).** The create-transaction screen posts without showing the journal first, because `@ledgerforce/bank` has no preview for `createTransactionFromLine`. Add a module preview that runs the posting engine up to *build* (no writes), a `POST /bank-rec/lines/:id/transaction/preview` route, and show the journal on the screen before "Post transaction".
- **Candidate suggestions.** Ambiguous receipt/payment candidates are listed as "Suggested: RCT-…", but neither the module nor the API can accept one. Add `acceptSuggestion` (method `suggestion`) to the module, a route, and a button on the match screen.
- **Large statement files.** Import sends the file as base64 JSON, and the API's default JSON body limit is 100 kB (about 75 kB of file). Raise the limit for this route only, or accept `multipart/form-data`. Test it with a file of several thousand lines.

## Acceptance criteria (each maps to a test)
- [ ] AC-1: the preview returns the journal lines (decimal strings) and writes nothing. → `packages/modules/bank/src/matching.db.test.ts`, `apps/api/src/bank/bank-rec.db.test.ts`
- [ ] AC-2: accepting a candidate suggestion matches the line to that entry. A closed suggestion is refused with 422. → same files
- [ ] AC-3: a 1 MB CSV imports over HTTP. → `apps/api/src/bank/bank-rec.db.test.ts`
- [ ] AC-4: the screen shows the journal before posting, and offers "Accept" on a candidate suggestion. → `tests/e2e/web/bank-rec.spec.ts`
