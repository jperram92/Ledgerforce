# T-0215 — Bills inbox transport: signed provider inbound webhooks (SaaS)

## Goal
Feed `ingestBillEmail` (T-0051) from a mail provider's inbound webhook for the hosted SaaS. Takes
over AC-2 of T-0127 (split by transport, DL-0810). RQ-0177 F4 / conclusion.

## Acceptance criteria
- AC-1 A Mailgun route `forward()` POST (raw MIME, recorded fixture) with a valid HMAC-SHA256
  signature over timestamp + token, to the company's inbound address, delivers one inbox item;
  a redelivery adds nothing → `apps/api/src/ap/bills-inbound-webhook.db.test.ts`
- AC-2 An unsigned, wrongly signed, stale (outside ±300 s) or replayed (token already seen)
  request is refused before anything is parsed or stored → same file
- AC-3 Tenant routing: the recipient's random inbound-address token resolves to one company via a
  narrow SECURITY DEFINER lookup; an unknown token is refused without revealing tenants; the
  `/webhooks/*` rate-limit class applies → same file + `packages/db/src/rls.db.test.ts`
