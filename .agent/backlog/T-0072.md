## Report (round 8, claude, 2026-10-26)

**Built**
- `salesforce/force-app/main/default/lwc/lfAccountSummary/`: a pure-LWC component for Account
  record pages (`js-meta.xml`: exposed, `lightning__RecordPage`, objects = Account, API 67.0).
  It uses two read wires and no Apex:
  - `getRecord` reads `LF_Balance_Due__c`, `LF_Overdue_Amount__c`, `LF_Last_Payment_Date__c` and
    `LF_Credit_Status__c` through `@salesforce/schema` imports.
  - `getRelatedListRecords` reads `LF_Invoices__r` with `pageSize: 5` and
    `sortBy: ['-LF_Invoice__c.LF_Issue_Date__c']`. UI API sorts and pages; the browser does neither.
  - Money is UI API's `displayValue`, falling back to `lightning-formatted-number` (format only).
    Dates fall back to `lightning-formatted-date-time` in UTC. Null mirror values show "—".
  - States: loading spinner, `role="alert"` error with no partial money, empty state, data table
    (caption, `scope="col"` headers, a `scope="row"` header per invoice, right-aligned amounts).
  - SLDS utility classes only (RQ-0088).
- LWC Jest: `@salesforce/sfdx-lwc-jest` 7.9.0 (DL-0218). `salesforce/jest.config.cjs` runs only
  `force-app/**/lwc/**/__tests__/**/*.test.js`. `pnpm test` = `vitest run … && pnpm test:lwc`,
  so verify gate 2a and CI's `pnpm test` step run it with no change to either. Jest fails on
  "No tests found" (spike, RQ-0045 S11).
- The spec fakes UI API from the config the component actually sends. It returns only the
  requested fields, sorts by the requested key and direction, and cuts the page to `pageSize`.
  So the "7 invoices → 5 most recent" assertion fails if the component asks for the wrong page,
  sort, list or fields.
- `salesforce/test/lwc-contract.test.ts` (Vitest, offline, 9 tests) checks:
  - the `pnpm test` → `test:lwc` chain, the exact pin and no `passWithNoTests`;
  - that every bundle has a spec;
  - the bundle metadata;
  - that every LF field the component reads is readable and not editable in `LF_Read_Only`;
  - that the component imports only the read adapters, with no Apex, record writes, fetch or
    number conversion.
  `salesforce/test/metadata.ts` now loads `LightningComponentBundle` metadata; before this, a
  `.js-meta.xml` file would fail the strict loader.
- ESLint now lints LWC JS (`lf/no-float-money` with the number-conversion ban). Prettier formats
  LWC JS/HTML with the `lwc` template parser (DL-0220).
