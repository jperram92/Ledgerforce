## Report (claude, parallel round 9)

**Built.** The Salesforce sync issues inbox in `apps/web/src/sync/`:
- `client.ts` calls the T-0071 routes.
- `logic.ts` holds the filter in the address, the status words, which action each status allows, and every connector error kind in plain words, with steps for known Salesforce codes.
- `SyncIssuesPage.tsx` is the list: status filter links, 20 per page, Next page / First page.
- `SyncIssuePage.tsx` is the detail page: what went wrong, what you can do (Retry / Ignore with an inline confirmation), attempts, and what it was sending with the payload on demand.

Routes are `/settings/sync-issues` and `/settings/sync-issues/$issueId`, listed on the Settings page (DL-0230). Styles are in `styles/sync.css`. There is no API, schema or dependency change: migration 0032 and ADR-0043 are unused.

**Tests.**
- `apps/web/src/sync/sync-logic.test.ts` and `sync.test.tsx`: 37 tests, RED captured first (missing module and route).
- `tests/e2e/web/sync-issues.spec.ts`: 13 tests, RED with the base router (13/13 failed), then GREEN. They cover 1440 and 390, light and dark, axe WCAG 2.2 AA, genericness probes, ≤ 1 primary action, no sideways scroll and no console errors.

**Evidence.** `.agent/evidence/T-0092/manifest.json` has 26 screenshots on e9b312c (plus an earlier identical run on c3eab53, kept because evidence is append-only) and the web test report `20261026-145930-tests-web.json`.

1. Ignored issues not retryable.
2. Default filter "all".
3. Salesforce code advice dropped.
4. Permission ignored (actions enabled for the Auditor).
