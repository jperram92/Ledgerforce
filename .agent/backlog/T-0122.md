# T-0122 — Tax determination part 1: schema and AU seed

## Goal
Implement the data side of **ADR-0044**: rules R1–R3 and R7. This covers:
- the `tax_class` columns on `app.party_posting_profile`, `app.product_posting_profile` and an
  optional override on `app.product`;
- the tenant-owned, effective-dated `app.tax_determination` table;
- seeding the AU cells from a new template `packages/modules/tax/templates/au-tax-determination.json`
  (or a section of the `au-gst` v2 template; decide at claim and log it).

`default_tax_code` gets a deprecation comment (R6). Nothing is dropped. The resolver change is
T-0123. Design §3.6, §4.4.

**Human gate.** ADR-0044 was accepted on 2026-11-08 by claude under DL-0282 after the
accountant-reviewer persona re-review DL-0285 found no BLOCKER (DL-0286; wording W1–W9 applied).
The gate is met. Build against the **accepted** ADR text, including R3's specificity order and
guard.

## Acceptance criteria (each maps to a test + SS id)
- [ ] **AC-1** (db-integration) Migration `00NN_tax_determination.sql` is additive (no DROP or
  RENAME). `app.tax_determination` has `tenant_id`, RLS ENABLE + FORCE and grants for `lf_app`.
  Both `party_tax_class` and `product_tax_class` accept a class or `*` (ADR-0044 R3, W1). A check
  or trigger enforces the R3 column rules: a `confirm` cell has `tax_code`, `alt_tax_code` and
  `confirmation_key`; a `manual` cell has no `tax_code`; a `code` cell has a `tax_code` and null
  `alt_tax_code` and `confirmation_key`. At most one valid row exists per literal key (company,
  direction, party class, product class) on a date. A treatment change is a new row (closes
  `valid_to`); there is no in-place update of `outcome` or `tax_code`. The test also proves:
  - **R3 guard (W2), in the database:** on direction `sale`, a `code` cell's `tax_code` and a
    `confirm` cell's `alt_tax_code` of any kind other than `taxable` (e.g. FRE, EXP, EXS, INP, N-T)
    are refused; a `confirm` cell's `tax_code` of kind `gst_free` is accepted; a referenced code that
    does not exist for the company, or is not valid on the row's `valid_from`, is refused.
  - **Author ≠ activator (W2, design §6.5 rule 5):** a new or replacing row records `created_by`
    and is not in effect until a different user activates it; activation by the author is refused
    (small-team mode as in §6.5).
  - **Back-dated rows (W6):** a row whose `valid_from` is earlier than its creation date without a
    reason is refused.
  → `packages/modules/products/src/tax-determination.db.test.ts`
- [ ] **AC-1b** (unit) The pure lookup over a snapshot picks the most specific matching row in the
  W1 order: exact party + exact product > `*` party + exact product > exact party + `*` product >
  `*` + `*`. In particular a tenant row `NON_RESIDENT_OFFSHORE × *` never beats the seed row
  `* × AU_REAL_PROPERTY`. The template loader applies the same R3 guard as the database and refuses
  a template that breaks it (a loader test with a guard-breaking fixture). →
  `packages/modules/products/src/tax-determination.template.test.ts`
- [ ] **AC-1c** (unit) The design §4.4 gap check also lists every active party tax class × product
  tax class × direction that has no matching cell (including through `*`) and is not
  product-inherent, so the wizard and nightly check show `NO_TAX_RULE` combinations before a
  document hits them. → `packages/modules/products/src/matrix.resolve.test.ts`
- [ ] **AC-2** (db-integration) `tax_class` values are constrained to the ADR-0044 R1/R2 lists, and
  a party class must match `party_kind`. `default_tax_code` carries the deprecation `COMMENT`. →
  same file
- [ ] **AC-3** (db-integration) Cross-tenant suite: tenant B cannot read or write tenant A's
  `app.tax_determination` rows. → the cross-tenant RLS suite (add the table to its registry)
- [ ] **AC-4** (unit) Every ADR-0044 R7 seed cell is present with the tabled outcome, code, alt and
  confirmation key. Template v2 profiles carry `tax_class` (DOMESTIC_CUSTOMER → DOMESTIC,
  OVERSEAS_CUSTOMER → NON_RESIDENT_OFFSHORE, DOMESTIC_SUPPLIER → DOMESTIC_REGISTERED, products
  classified, EQUIPMENT → CAPITAL_EQUIPMENT). →
  `packages/modules/products/src/tax-determination.template.test.ts`
- [ ] **SS-PLAT-131**: add a register row at claim: "Tax determination matrix is seeded per
  company, is tenant-isolated and is changed only by effective-dated rows."
