# T-0122 — Tax determination part 1: schema and AU seed

## Goal
Implement the data side of **ADR-0044**: rules R1–R3 and R7. This covers:
- the `tax_class` columns on `app.party_posting_profile`, `app.product_posting_profile` and an
  optional override on `app.product`;
- the tenant-owned, effective-dated `app.tax_determination` table;
- seeding the AU cells from a new template `packages/modules/tax/templates/au-tax-determination.json`
  (or a section of the `au-gst` v2 template; decide at claim and log it).

`default_tax_code` gets a deprecation comment (R6). Nothing is dropped. The resolver change is
T-0123. Design §3.6, §4.4.

**Human gate.** ADR-0044 is `Proposed`. Under DL-0282, claude may accept it after an
accountant-reviewer persona re-review with no BLOCKER. This card may be built test-first on its
branch before acceptance, but it cannot reach `done` until ADR-0044 is Accepted. ADR acceptance
is a gate, not a card, so it is not listed in `depends_on`.

## Acceptance criteria (each maps to a test + SS id)
- [ ] **AC-1** (db-integration) Migration `00NN_tax_determination.sql` is additive (no DROP or
  RENAME). `app.tax_determination` has `tenant_id`, RLS ENABLE + FORCE and grants for `lf_app`. A
  check or trigger enforces the R3 column rules: a `confirm` cell has `tax_code`, `alt_tax_code`
  and `confirmation_key`; a `manual` cell has no `tax_code`. At most one valid row exists per
  (company, direction, party class, product class, date). A treatment change is a new row (closes
  `valid_to`); there is no in-place update of `outcome` or `tax_code`. →
  `packages/modules/products/src/tax-determination.db.test.ts`
- [ ] **AC-2** (db-integration) `tax_class` values are constrained to the ADR-0044 R1/R2 lists, and
  a party class must match `party_kind`. `default_tax_code` carries the deprecation `COMMENT`. →
  same file
- [ ] **AC-3** (db-integration) Cross-tenant suite: tenant B cannot read or write tenant A's
  `app.tax_determination` rows. → the cross-tenant RLS suite (add the table to its registry)
- [ ] **AC-4** (unit) Every ADR-0044 R7 seed cell is present with the tabled outcome, code, alt and
  confirmation key. Template v2 profiles carry `tax_class` (DOMESTIC_CUSTOMER → DOMESTIC,
  OVERSEAS_CUSTOMER → NON_RESIDENT_OFFSHORE, DOMESTIC_SUPPLIER → DOMESTIC_REGISTERED, products
  classified, EQUIPMENT → CAPITAL_EQUIPMENT). →
  `packages/modules/products/src/tax-determination.template.test.ts`
- [ ] **SS-PLAT-131**: add a register row at claim: "Tax determination matrix is seeded per
  company, is tenant-isolated and is changed only by effective-dated rows."
