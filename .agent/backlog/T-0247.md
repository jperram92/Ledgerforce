# T-0247 — Restore-drill db test: intermittent unhandled 57P01 after the run

## Goal
While validating T-0244, one of five local runs of
`packages/ledger/src/ops/restore-drill.db.test.ts` (with the backup-role files) passed every test
but Vitest reported one unhandled error: a pooled `pg` client (user `postgres`, database
`postgres`) received `57P01 terminating connection due to administrator command`, attributed to
the restore-drill file. The other four runs, and two runs of the file alone, were clean. The
likely cause is an idle client still open when the file's own throw-away target cluster is
stopped in `afterAll` (fast shutdown terminates sessions), or an idle pool without an `error`
listener. Evidence: `.agent/evidence/T-0244/flake-restore-drill-57P01.txt`.

## Acceptance criteria
- [ ] AC-1 find which client receives 57P01 (pool or client, which cluster) and close it before
      the cluster stops, or attach an error listener where a terminated idle connection is expected
- [ ] AC-2 20 consecutive local runs of the restore-drill file together with the backup-role db
      files report no unhandled error

- [ ] 2. Fix and repeat runs
