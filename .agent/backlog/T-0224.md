# T-0224 — Bills inbox transport: Postmark inbound (Basic credentials) and AWS SES via S3 + SNS

## Goal
Postmark inbound (JSON, `RawEmail`, `OriginalRecipient`) authenticated only by per-deployment Basic credentials over TLS (documented weaker than a signature, RQ-0181 S7) plus optional source-IP allowlist; SES receipt rule → S3 action + SNS notification with X.509 signature verification (SignatureVersion 2, certificate URL host `sns.<region>.amazonaws.com`), message fetched from S3 by the worker. Replay key and tenant routing reuse ADR-0099.

## Acceptance criteria
- AC-1 Postmark: a recorded inbound JSON with the right Basic credentials delivers one inbox item; wrong/missing credentials refused before parsing; the MessageID is the replay key
- AC-2 SES: a recorded SNS notification with a valid signature (test certificate) enqueues the S3 fetch; a bad signature, a certificate URL off `amazonaws.com` or a stale timestamp is refused; SubscriptionConfirmation handled
- AC-3 Both route by the recipient token through `app.bill_inbox_route()` and refuse unknown tokens without tenant detail
