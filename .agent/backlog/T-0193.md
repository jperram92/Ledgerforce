# T-0193 — Change ABA details or archive a company bank account

## Goal
Found while building T-0185 (DL-0704). Wizard step 4 needs a bank account with an APCA user id and
an ABA user name. `lf_app` may update only `name`, `status` and `csv_mapping` of
`app.bank_account` (migration 0013), and no route archives an account, so an account added
without its ABA details cannot be completed in the app. Let an Owner or Finance Admin set the APCA
user id, ABA user name and FI mnemonic of an existing account, and archive an account, with the
controls of a bank-detail change.

## Context (design refs)
- Design §4.1 step 4, §6.2 (step-up for bank-detail changes), §6.6, §6.8; RQ-0166 finding 7;
  ADR-0084; ADR-0080 (an archived remittance account; coordinate with T-0191).

## Acceptance criteria (each maps to a test + SS id)
- [x] **AC-1** — Migration grants UPDATE on the three ABA columns only (additive), with a DB test
  that the number columns stay immutable for lf_app.
- [x] **AC-2** — `PUT /setup/bank-accounts/:id/aba` and `POST /setup/bank-accounts/:id/archive`

  `changed:false`) → api-db test; the bank accounts screen offers both.
