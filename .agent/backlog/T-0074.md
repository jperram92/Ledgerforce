# T-0074 — Stripe webhooks (signed, replay-protected) → receipt into clearing

## Goal
Verify signature + timestamp tolerance; payment succeeded → GP-003 receipt allocated to invoice; idempotent by event id.

## Context (design refs)
- Design: §6.9 signed webhooks, §3.8 row 3.
- Specs: [UC-03](../../Docs/specs/UC-03.md), [UC-11](../../Docs/specs/UC-11.md) · Register: [success-scenarios.md](../../Docs/specs/success-scenarios.md)

- [ ] postings Q1/Q2.

## Acceptance criteria (each maps to a test + SS id)
- [ ] **SS-UC03-02** (golden) — Stripe payment posts GP-003 and marks invoice Paid. *Given* a signed payment-succeeded webhook for INV-000123; *when* it is processed; *then* the journal equals GP-003 and the invoice status is Paid.
- [ ] **SS-UC03-04** (contract) — Salesforce shows Paid with payment date. *Given* SS-UC03-02 processed; *when* write-back runs; *then* the sObject Collections payload sets LF_Invoice__c status Paid with payment date, Opportunity LF_Amount_Paid__c 1,375.00 and Account LF_Balance_Due__c reduced.
- [ ] **SS-UC03-05** (db-integration) — Duplicate webhook is idempotent. *Given* the same Stripe event delivered twice; *when* both are processed; *then* one receipt and one journal exist.
- [ ] **SS-UC03-06** (unit) — Invalid or replayed webhook rejected. *Given* a webhook with a bad signature, and one with a timestamp outside tolerance; *when* they are received; *then* both return 400 and nothing is posted.
- [ ] **SS-UC11-04** (contract) — Refund via Stripe calls the refund API. *Given* the credit and an original Stripe charge; *when* refund via Stripe is chosen; *then* a Stripe refund request for 220.00 is sent (recorded API) and the journal credits Stripe clearing.
