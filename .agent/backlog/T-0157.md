# T-0157 — Setup wizard over HTTP

## Goal
Split from T-0123 (DL-0523): the HTTP contract of the persisted setup wizard (design §4.1,
ADR-0067 rule 6) on top of `wizardOf` / `completeWizardStep` in `@ledgerforce/setup`. The UI
(T-0091) reads and completes steps only through these routes.

## Context (design refs)
- Design §4.1, §6.4 (permissions), apps/api/AGENTS.md (idempotency key, audit, tenant tx).
- Module API built in T-0123: `wizardOf(trx, companyId, { asOf })`,
  `completeWizardStep(trx, { companyId, step, completedBy, noHistoryReason? , asOf })`,
  refusals `WizardError` codes `STEP_LOCKED`, `STEP_INVALID` (with `missing[]`),
  `NO_HISTORY_NOT_ALLOWED`, `INVALID_COMMAND`.

## Acceptance criteria (each maps to a test + SS id)
- [ ] AC-1 `GET /setup/wizard?company_id=` returns the ten steps (status, locked, valid, missing)
  and `complete` → `apps/api/src/setup/wizard.db.test.ts` (SS-PLAT-120)
- [ ] AC-2 `POST /setup/wizard/steps/:n/complete` (idempotency key required; 201 new / 200
  replay; audited) completes a valid unlocked step; a locked step is 409 `STEP_LOCKED`; an
  invalid one 422 `STEP_INVALID` with `missing`; step 9 accepts `{ no_history_reason }` → same
  file (SS-PLAT-120)
- [ ] AC-3 both routes need `settings.chart.manage` (403 otherwise); another tenant's company is
  404 → same file (SS-PLAT-120)

## Open questions (→ research before start)
- Confirm the permission (`settings.chart.manage`, as the opening-balance routes) or a dedicated
  `settings.setup.manage`; a new permission is a security change (human gate).
