# T-0145 — AR write-off: resolve the ECL allowance by the AR_ECL_ALLOWANCE role

## Goal
Design §3.2 resolves accounts by role. Since T-0117 (ADR-0061) AR_ECL_ALLOWANCE is a bound system
role, but `packages/modules/ar/src/write-off.ts` still reads the allowance account from
`app.ar_settings.ecl_allowance_account_id` and refuses a write-off when it is not set. Post the
allowance line as `{ role: 'AR_ECL_ALLOWANCE' }` (GP-024, GP-038/039) and decide what the
setting becomes (explicit override or deprecated: data shape change → DL entry, ADR if the
column is deprecated).

## Acceptance criteria (each maps to a test)
- AC-1 Given a company whose template bound AR_ECL_ALLOWANCE and no ar_settings allowance,
  when a debt is written off via the allowance, then the journal matches GP-024 line for line
  → `packages/modules/ar/src/write-off.db.test.ts`.
- AC-2 The gross-allowance lifecycle (GP-038/039) still replays → `packages/modules/ar/src/gross-allowance.db.test.ts`.
- AC-3 The remaining-allowance query reads the role-bound account → `write-off.db.test.ts`.

## Open questions
- Keep `ecl_allowance_account_id` as an override of the role, or deprecate it (comment + ADR)?
