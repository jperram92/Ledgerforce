# T-0108 — OpenBao/Vault transit KMS adapter

## Goal
A second `Kms` adapter (packages/shared/src/crypto) that wraps and unwraps data keys through the
transit engine of OpenBao (MPL 2.0) or Vault over HTTP with `fetch`, so operators who run a
secrets manager can keep KEKs out of the app host (ADR-0018 consequence).

## Report (claude, 2026-10-26, parallel round 7)

**Built** (branch `feat/T-0108-openbao-transit-kms`, base 4263ce7; no migration, 0031 unused):

- `packages/shared/src/crypto/transit-kms.ts` — `TransitKms implements Kms` over Node `fetch`
  (no SDK, no new dependency). It works as follows:
  - **Binding.** The key must be a derived `aes256-gcm96` key, and every call sends the context
    `lf-kek-transit-v1|<record aad>`. Server-side rewrap still works with this binding.
  - **Storage.** `wrapped` is the 60 decoded bytes and the key id is `tr.<key>.v<N>`, so both
    fit the existing columns.
  - **Key policy.** `connect` refuses a key that is not derived, is convergent, is exportable,
    allows plaintext backup, or is not `aes256-gcm96`.
  - **Transport.** https only; loopback `http:` needs explicit opt-in. Redirects are refused. Each
    attempt has a timeout. 429, 5xx, network errors and timeouts are retried with full-jitter
    backoff and `Retry-After`, capped. 4xx is never retried.
  - **Auth.** A static token, or AppRole: it logs in again at two-thirds of the lease and once
    after a 403. `X-Vault-Namespace` is supported.
  - **Failures.** A 400 on decrypt or rewrap raises `DecryptionError`. Other failures raise
    `TransitKmsError(op, kind, status)` with no server text. Log events carry only op, outcome,
    attempt, ms, status, kind and a fixed reason code.
- `envelope.ts`: optional `Kms.rewrap` + `rewrapField` (additive; the local keyring falls back to
  unwrap+wrap). The existing SS-PLAT-38 tests are unchanged and green.
- `kms-config.ts`: `kmsFromEnv` — `LF_KMS_PROVIDER` unset → `null` (MVP unchanged), `local`,
  `transit` (`LF_KMS_TRANSIT_*`, secrets only from files).
- Tests:
  - `testing/fake-transit.ts` is the fake, with fault injection.
  - `testing/transit-contract.ts` is the raw HTTP contract.
  - `testing/kms-contract.ts` is the SS-PLAT-38 contract plus rotation and rewrap.
  - `transit-kms.test.ts` holds 62 new tests.
  - `transit-kms.openbao.itest.ts` holds 17 tests against real OpenBao.
- `scripts/test/openbao.sh` + `pnpm test:openbao` + Vitest project `openbao` (DL-0204).
- Docs: RQ-0042 (with spike scripts and outputs in `Docs/research/assets/RQ-0042/`), ADR-0038
  (security, Proposed), DL-0200..DL-0204, SS-PLAT-87/88 (green), totals 172 (19 screenshots).

**Not proven / limits:**

- Vault itself (BUSL) was not run; compatibility with Vault is inference.
- The release checksum list is not signed at any URL I could find, so the SHA-256 is pinned on
  first use.
- The DEK passes through JS strings (base64 JSON), which cannot be zeroed.
- `NODE_EXTRA_CA_CERTS` is process-wide.
- The fake does not model ACLs or batch input. The real run covers the ACL path.
