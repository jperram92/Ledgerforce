# T-0228 — Point-in-time recovery (split from T-0143, DL-0885)

## Goal
Design §6.9 targets RPO 15 minutes / RTO 4 hours for hosted. T-0143 ships nightly logical
backups (RPO 24 h) for the single VM. Provide PITR: physical base backups plus continuous WAL
archiving (managed Postgres PITR for hosted; pgBackRest or WAL-G, encrypted, as an optional
compose profile for self-hosters), and extend the restore drill to restore to a point in time
and run the same row-count and hash-chain checks.

## Acceptance criteria
- AC-1 Research and ADR: pgBackRest vs WAL-G vs managed PITR; encryption and key custody aligned
  with ADR-0101; new dependency ADR if an image or tool is added
- AC-2 A drill restores to a target time between two postings and every company's chain verifies
  with exactly the entries committed before that time → db/integration test (local cluster)
- AC-3 Runbook section for PITR in `Docs/ops/backup-restore.md`

## Open questions
- Which tool, and whether self-host PITR is in MVP scope or hosted-only (design §6.9 says hosted).
