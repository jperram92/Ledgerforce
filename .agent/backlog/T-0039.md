## Open questions (→ research before start)
- None known at creation. At claim (2026-11-08) T-0038 left two: account precedence (override → product slot → party default?) and which tax code wins (party profile default vs product default). Resolved in [RQ-0097](../../Docs/research/RQ-0097-posting-profile-resolution-precedence.md): account = override → product slot → PROFILE_GAP (the design gives a party profile no account slot besides its control account); tax code = explicit line code → the single/equal default → refuse TAX_CODE_CONFLICT / NO_TAX_CODE. A fixed precedence between differing defaults is a tax treatment left to the human/accountant (HANDOVER question).
