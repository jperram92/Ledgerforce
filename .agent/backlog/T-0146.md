# T-0146 — GL: re-bind a system role (core or period-end) through the API

## Goal
Design §3.2: system roles are bound at setup and re-bound, never unbound. The database supports
re-binding by UPDATE of `account_id` in `app.account_system_role` (0005) and
`app.account_system_role_ext` (0062, ADR-0061), but no module function or API route does it.
Add `rebindSystemRole(trx, { companyId, role, accountId })` in `packages/modules/gl` that writes
to `bindingTableFor(role)`, audits the change, and an API route with a permission, so the chart
UI and setup wizard can move a role to another account of an allowed type.

## Acceptance criteria (each maps to a test)
- AC-1 Re-binding a core role and a period-end role updates the right table and
  `app.account_role_binding` shows the new account → `packages/modules/gl/src/rebind.db.test.ts`.
- AC-2 A re-bind to an account of a disallowed type, archived, or non-postable is refused with
  the database message → `rebind.db.test.ts`.
- AC-3 The route needs the GL admin permission and writes an audit row → API test.

## Open questions
- Which permission (existing `gl.admin`-style permission or a new one)? Check the permission
  catalogue first.
