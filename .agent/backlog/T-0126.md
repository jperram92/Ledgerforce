# T-0126 — Tax report: EXP lines without export evidence and past 60 days

## Goal
Implement the tax-report part of **ADR-0044 R4** (wording W5, persona re-review DL-0285 MAJOR M5).
For `s38-185` the export evidence reference may be blank when the user confirms, because the
goods usually leave after the invoice. The tax report must therefore list every **posted** line
coded `EXP` whose confirmation record has no evidence reference, and flag those whose 60-day
period has passed. The user then records the evidence or corrects the supply (adjustment note or
credit note; posted = immutable). Without this list a missed export stays GST-free and the BAS
stays understated.

This is a follow-up to T-0035 (BAS box mapping and tax report query), which is being built on its
own branch. T-0035's card is not edited; this card adds the list next to its report. It reads
the R4 confirmation record that T-0123 creates. Design §3.6.

## Acceptance criteria (each maps to a test + SS id)
- [ ] **SS-PLAT-136 / AC-1** (db-integration) For a company and an as-of date, the report returns
  every posted `EXP` line (document, line, party, amount ex GST, document tax date, confirmation
  key `s38-185`, confirmed by/at) whose confirmation has a blank evidence reference. Lines whose
  evidence reference is set are not listed; draft documents are not listed; other tenants' and
  other companies' lines are never visible (RLS). → 
  `packages/modules/tax/src/export-evidence-report.db.test.ts`
- [ ] **AC-2** (unit) The 60-day flag: a line is `overdue` when the as-of date is more than 60 days
  after the earlier of the first consideration received and the invoice date (for instalments,
  the final instalment or its invoice), following the ADR-0044 `s38-185` condition text. Boundary
  cases at day 60 and day 61 are tested, and a line with no consideration yet counts from the
  invoice date. An ATO-allowed extension is out of scope: it is shown as a note and not computed.
  Dates are plain calendar dates; there is no money arithmetic in this rule. →
  `packages/modules/tax/src/export-evidence-report.test.ts`
- [ ] **AC-3** (db-integration) Recording an evidence reference after posting is an append to the
  confirmation's evidence (a new evidence row or the R4 table's append path chosen in T-0123),
  never an UPDATE of the frozen confirmation. Afterwards the line leaves the list. → same file as
  AC-1

## Open questions
- Whether T-0123 stores evidence added after posting as a separate append-only evidence row or
  as a new confirmation version. Read T-0123's DL entry at claim and follow it. If neither exists,
  add an additive evidence table here with RLS and cross-tenant coverage (`migration` skill), and
  log it.
- Instalment detection: confirm from the invoice and receipt model (T-0040/T-0046) how "final
  instalment" is known. If it cannot be known, use the earlier of the first consideration and the
  invoice date (the earliest, so the flag errs early) and log the choice.
