## Report (T-0028, claude, round 7)

**Built**
- Migration `0028_ledger_subledger_allocation.sql`: `app.subledger_entry` (one per line on an
  AR_CONTROL/AP_CONTROL account; filled from the line by a BEFORE INSERT trigger; signed like
  the GL; transaction and base amounts; CHECK `0 ≤ |open| ≤ |original|` on the original's side)
  and append-only `app.allocation` (SECURITY DEFINER triggers lock both items FOR UPDATE in id
  order, refuse over-allocation, price base releases and `fx_difference`, apply the deltas).
  Guards: items change only open amounts and only from the allocation trigger; allocations never
  change; no DELETE/TRUNCATE. lf_app SELECT/INSERT only; RLS ENABLE+FORCE; cross-tenant suite
  covers both tables.
- Posting engine: `BuiltEntry.subledgerItems` (preview parity), items written in the write
  savepoint; `PostingLineInput.dueDate` (AR/AP control lines only).
- `packages/ledger/src/subledger.ts`: `allocate`, `reverseAllocation` (idempotency keys,
  advisory locks, typed `AllocationError`), `openItem`, `openItems`, `subledgerEntriesOf`,
  `subledgerReconciliation` (read API for SS-UC10-08), `subledgerDrift`.
- Tests: `subledger.allocation.db.test.ts` (14), `subledger.prop.db.test.ts` (fast-check,
  default numRuns: INV-ar-control, INV-ap-control, INV-allocation), one unit test in
  `posting-command.test.ts`. RED captured first (module missing). Mutation check: 9 hand
  mutants, all killed (`.agent/evidence/T-0028/mutation-check.txt`).
- Docs: RQ-0039, ADR-0035 (accounting, Proposed), DL-0185..0189, SS-PLAT-81..82.

**Open questions for the human**
1. ADR-0035 (accounting, Proposed): accept the open-item sign convention, base pricing of
   allocations and the meaning of `fx_difference`.
2. Realised FX at allocation (DL-0187): the golden posting is Draft, so no FX journal is posted
   and the reconciliation reports `unpostedFxDifference`. Approve the golden posting to let a
   follow-up post it.
3. Should every AR/AP control line carry a party? Today an item may have no party (existing
   engine tests post such lines, and their assertions cannot change).
4. DL-0136/DL-0139 still apply: which source types may post to each control account.
