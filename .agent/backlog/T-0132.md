# T-0132 — Approve one invoice over HTTP (split from T-0131)

## Goal
`POST /ar/invoices/:id/approve`, so the T-0083 detail screen can approve and post a draft.

## Open questions
- [x] Which permission governs approving a single invoice? The catalogue has `ar.invoice.create`, `ar.invoice.send`, `ar.batch.approve` and no `ar.invoice.approve`. Design §6.4/§6.5 (RBAC/SoD) and UC-01 decide whether to add a permission and which role templates get it. That is a **security** ADR (role templates, ADR-0023). Resolved: `ar.invoice.approve` (ADR-0072); the SoD rule and route contract in ADR-0073 (DL-0477, DL-0561).

## Acceptance criteria
- [ ] AC-1: Approve with the chosen permission posts GP-001 (equal to the T-0131 preview); a replay is idempotent; a user without the permission gets 403; the SoD rule (creator ≠ approver if required) is applied.
- [ ] AC-2: RBAC matrix test updated for the new permission.
- [ ] AC-3 (e2e, SS-UC01-13): the invoice screen shows "Approve and post" after the journal preview only to holders of `ar.invoice.approve`; a refusal (SoD, already posted, rule) is explained in plain words; screenshots at 1440 and 390 with axe and the genericness probe. Added 2026-11-14 by the lead brief (DL-0570).
