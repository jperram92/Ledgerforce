# T-0123 — Setup wizard state machine and step validators (steps 1–10)

## Goal
The persisted wizard of design §4.1: per company, steps 1–10 with a status (not started, in
progress, complete), unlocked in order, each completed only when its validator — which reads the
owning module's state and never duplicates it — passes; the wizard is complete when all ten are.
Split from T-0080 (DL-0314), which built step 9's backend (opening balances, GP-037).

## Context (design refs)
- Design: §4.1, §4.4 (gap check), §5 (Salesforce connection). Register:
  [success-scenarios.md](../../Docs/specs/success-scenarios.md)
- Step 9's validator: an opening balance is posted (`openingBalanceOf` in `@ledgerforce/setup`,
  T-0080) or the company records that it has no history (new business) with a reason.

## Open questions (→ research before start) — answered in RQ-0149 (DL-0520, DL-0521)
- Steps 3, 8 and 10 need settings that no module persists yet on the build line (GST basis and BAS
  frequency; numbering, branding, payment terms and payment methods; approval thresholds beyond the
  SoD settings). Decide which module owns each (research + decision log) before writing
  validators; the wizard must not own them.
- Which steps may be skipped (e.g. step 9 for a new business) and who may skip them.
