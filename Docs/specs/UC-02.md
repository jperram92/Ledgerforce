## Actors / roles
AR Clerk (runs batch), Approver/Finance Admin (approves where required)

## Preconditions
- 40 active billable Accounts with billing plans/lines for the period.
- Batch billing template configured (§4.3).
- Open period for AR.

## Trigger
Scheduled run (e.g. 1st of month) or manual run by the AR Clerk.

## Main flow
1. AR Clerk selects period and template; system selects billable Accounts.
2. Preview lists every invoice with totals and warnings; nothing written to the ledger.
3. Clerk (or approver) approves the batch.
4. One job posts every invoice, each in its own transaction, numbering consecutively.
5. PDFs email to each Billing To and CC contact.
6. Batch summary journal report is available.

## Alternate and failure flows
- A1 One invoice fails (gap, inactive party, validation) → it lands in the exception list; others post.
- A2 Job crashes mid-run → re-run continues; no duplicates.
- A3 Email bounce → logged against the invoice; posting unaffected.

## Business rules
- Batch preview uses preview mode (§3.9).
- Per-invoice isolation (UC-02 second bullet).
- Gapless numbering; failed invoices consume no number (§3.4).

## Data touched (LedgerForce)
billing_batch, invoice, journal_*, subledger_entry, email_log, outbox

## Salesforce fields touched

- Phase: MVP · Layer: **db-integration** · Screenshot evidence: no · Task(s): T-0043

- **When** the AR Clerk runs a batch preview for November

### SS-UC02-02 — Approved batch posts all invoices in one job
- Phase: MVP · Layer: **db-integration** · Screenshot evidence: no · Task(s): T-0044
- **Given** the SS-UC02-01 preview
- **When** the batch is approved
- **Then** 40 invoices are posted by one job, each journal matches the posting rules, and a batch summary report lists 40 entries

### SS-UC02-03 — One failure does not roll back the others
- Phase: MVP · Layer: **db-integration** · Screenshot evidence: no · Task(s): T-0044
- **Given** 40 Accounts where one has an inactive party
- **When** the approved batch runs
- **Then** 39 invoices post, 1 is in the exception list with its reason, and no posted invoice is rolled back

### SS-UC02-04 — PDFs emailed to Billing To and CC
- Phase: MVP · Layer: **db-integration** · Screenshot evidence: no · Task(s): T-0044, T-0042
