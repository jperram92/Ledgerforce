## Actors / roles
Finance Admin, Accountant, AR/AP Clerks, two approvers for reopen

## Preconditions
- Period October open; bank accounts reconciled through October.

## Trigger
Finance Admin starts the October close checklist.

## Main flow
1. AR lock → AP lock → bank recs complete → accruals → review TB → soft close → hard lock after BAS.
2. Each step recorded with user and time.
3. Later postings dated October rejected or redirected per policy.

## Alternate and failure flows
- A1 Bank recs incomplete → cannot pass that step.
- A2 Override user posts AR in AR-locked period → allowed and audited.
- A3 Reopen from hard lock → two approvers + reason.

## Business rules
- §3.5 status matrix; §6.5 rule 6; §2 lock policy.

- Phase: MVP · Layer: **db-integration** · Screenshot evidence: no · Task(s): T-0078
- **Given** period October
- **When** the Finance Admin completes each step

### SS-UC10-02 — AR lock blocks AR posting except with override
- Phase: MVP · Layer: **db-integration** · Screenshot evidence: no · Task(s): T-0023, T-0078
- **Given** October AR-locked
- **When** an AR Clerk posts an October invoice, then an override user does
- **Then** the first is rejected; the second succeeds and is audited; AP bills still post

### SS-UC10-03 — AP lock allows journals only
- Phase: MVP · Layer: **db-integration** · Screenshot evidence: no · Task(s): T-0023
- **Given** October AP-locked
- **When** a bill, an invoice and a manual journal are posted for October
- **Then** bill and invoice rejected, journal accepted

### SS-UC10-04 — Soft close: Finance Admin override only
- Phase: MVP · Layer: **db-integration** · Screenshot evidence: no · Task(s): T-0023
- **Given** October soft-closed

### SS-UC10-05 — Hard lock rejects or redirects per policy
- Phase: MVP · Layer: **db-integration** · Screenshot evidence: no · Task(s): T-0023, T-0078
- **Given** October hard-locked
- **When** a document dated October is posted under each lock policy
- **Then** "reject" → PERIOD_LOCKED; "first open date" → dated 2026-11-01 with note

### SS-UC10-06 — Reopen needs two approvers and a reason
- Phase: MVP · Layer: **db-integration** · Screenshot evidence: no · Task(s): T-0079

- **When** one approver requests reopen; then a second distinct approver approves with a reason
