# Decisions, ADRs and change logs — how they fit together

LedgerForce keeps a **two-tier decision record** plus two different kinds of change log. All of
them live in the repository because the repository is the only memory (AGENTS.md §0.1).

## Tier 1 — the decision log (`Docs/decisions/decision-log.md`)

- **Every** decision, big or small, chronological, newest at the bottom: tool choices, naming,
  workarounds for environment blocks, interpretation of an ambiguous requirement, scope calls.
- One short entry (`DL-NNNN`): date, who (human / claude / codex), task, category, decision,
  why (with RQ links or sources), alternatives, ADR link, status. Format is at the top of the log.
- Append-only: never edit or delete a merged entry. A reversal is a new entry
  `Supersedes DL-NNNN`; the old entry only gains a trailing `Superseded by DL-MMMM` note.
- Skill: `log-decision`.

## Tier 2 — Architecture Decision Records (`Docs/adr/`)

- **Significant** decisions only — the design §10.6 triggers: data model, accounting treatment,
  security model, public API, integration contract, new runtime dependency (plus process/tooling
  decisions that constrain every future task).
- Full MADR reasoning: context, drivers, options with pros/cons, outcome, consequences, and how
  tests/CI verify compliance. Lifecycle, human gates and the index: [`Docs/adr/README.md`](../adr/README.md).
- Skill: `write-adr`.

## Cross-linking rules

1. Every ADR has at least one DL entry; the entry's `ADR:` field names it (`ADR-0004`), and the
   ADR's *Links* section names the DL entry (`DL-0007`).
2. A DL entry with `ADR: none` is a small decision; if it later turns out to be significant,
   write an ADR and add a new DL entry linking both — do not rewrite the old entry.
3. When an ADR is superseded, add a DL entry recording the change, and update the forward link
   on the old ADR.
4. Research records (`Docs/research/RQ-NNNN-*.md`) hold the evidence; DL entries and ADRs cite
   them rather than copying them.
5. Task cards (`.agent/backlog/T-NNNN.md`) and `HANDOVER.md` mention decisions by id
   ("Decisions taken: DL-0042; follows ADR-0004").

## How the change logs differ

| | `CHANGELOG.md` (repo root) | `.agent/runs/<date>-<run>.md` |
|---|---|---|
| What | **Product log** — what changed for users/operators of LedgerForce | **Operational log** — what one agent session did |
| Audience | Users, self-hosters, release reviewers | The next agent, the product owner, auditors of the build process |
| Granularity | Per release (Keep a Changelog: Added, Changed, Fixed, Security…) | Per session: provider, start/end, tasks touched, commits, tests run, cost estimate, why it stopped |
| How written | Hand-maintained `Unreleased` during Sprint 0; generated by release-please from Conventional Commits from the first release onward (design §10.7) | Written by the agent at the end of every session (skill `run-log`) |
| Decisions? | Mentions notable ADRs in release notes | Lists the DL/ADR ids taken during the session |

Neither log replaces the decision record: logs say *what happened*, decisions say *why*.
